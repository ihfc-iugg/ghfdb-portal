# Implementation Plan: Demo data for development

**Branch**: `008-demo-data` | **Date**: 2026-10-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/008-demo-data/spec.md`

## Summary

`manage.py seed_demo_data --size N` adds demo data to a development database:

1. It refuses outside development, the way FairDM's `create_dev_accounts` does.
2. It loads the vocabularies and licences.
3. It makes sure the development accounts exist.
4. It creates `N` datasets. Each one gets its own transaction and its own deferred quality
   recalculation, and holds:
   - a demo literature item
   - the dataset and its contributors
   - the dataset's assessment
   - the heat flow graph beneath it

Scores are computed when each dataset's block ends. Repeated runs add more and never touch anything
that is not demo data.

The heat flow graph is generated by `project/heat_flow/demo.py`, which knows nothing about
assessments. The command lives in `project/review/management/commands/seed_demo_data.py` and
composes everything else. There are no new dependencies and no migrations.

## Technical Context

**Language/Version**: Python 3.13, Django 5.2

**Primary Dependencies**:

- FairDM: `preload`, `seed_licenses`, `create_dev_accounts`, `Contribution.add_to` and
  `NON_PRODUCTION_ENVIRONMENTS`
- research-vocabs
- the standard library's `random`

No new dependency. `factory_boy` and `faker` stay test-only.

**Storage**: PostgreSQL with PostGIS. No migration.

**Testing**: pytest with `call_command`, against the test database with concepts preloaded by
`tests/conftest.py`. The command's tests run at the smallest size, 4 datasets.

**Performance**:

- Plain models are written with `bulk_create`.
- The six multi-table models are saved one at a time (research R1).
- Each dataset is one transaction, and nothing accumulates across datasets, so memory stays bounded
  (FR-015).
- No run time is set (Sam, 2026-10-20).

## Constitution Check

- **Tests first**: every task writes its failing test first.
- **Normalised model**: nothing about the model changes, and the generator writes only through it.
- **Quality computed here**: scores are computed by `Recalculation`, never generated (FR-008).
- **`heat_flow` owns the model, `ghfdb` reads it**: `ghfdb` is untouched. The one new import
  direction is `review` → `heat_flow` (research R10).
- **A parent is designated, never calculated**: the generator designates one parent per site
  explicitly. Relevance is set on the children, as an assessor would set it.

## Design

### `project/heat_flow/demo.py`: the heat flow graph

**`REGIONS`** is a tuple of `Region` named tuples. Each one holds:

- `name`
- `min_lat`, `max_lat`, `min_lon`, `max_lon`
- `marine`, a bool
- `environment`, a value of `HeatFlowSite.environment_vocab.values`
- `explo_method`, a value of `HeatFlowSite.explo_method_vocab.values`: `probing_offshore` for marine
  boxes, `drilling` for land boxes, so that `route()` picks the probe or borehole rules

There are about twenty boxes where heat flow is measured, roughly 40 % marine (research R4).

**`DemoGraph(dataset, rng, next_ghfdb_id=None)`** builds one dataset's graph with
`build(sites=SITES_PER_DATASET)`:

- `rng` is a `random.Random`.
- `next_ghfdb_id` is a callable returning the next published identifier, or `None` for an
  unpublished dataset (research R8).

For each site, `build()` does the following:

1. **Place the site.** Pick a region and draw a point at five decimal places. On a
   `ValidationError` from the site's coordinate check, redraw, up to ten times, then raise. Create
   the site with `HeatFlowSite.objects.create(...)`:
   - `type` and an `elevation` in the region's range
   - `explo_method` and `environment` from the region
   - `name` and `local_id` of the form `DEMO-<dataset pk>-<n>`
2. **Create the parent.** `ParentHeatFlow.objects.create(sample=site, ...)`.
3. **Create the children.** The number of children is taken from `CHILDREN_CYCLE = (1, 2, 3, 4)`
   by the site's position, which gives 50 per dataset. For each child:
   - Create a `HeatFlowInterval` with `site=site`. A borehole interval's top is at 0–1,500 m and it
     is 50–1,500 m thick. A probe interval runs from 0 m to 2–10 m. Top is always above bottom.
   - Create a `ThermalGradient` and an `IntervalConductivity` on that interval.
   - Create the `HeatFlow` with `thermal_gradient`, `thermal_conductivity` and `parent` set, and
     `value` equal to the gradient times the conductivity.
   - Set `is_relevant` true, except on a parent with three or more children, where the last child
     is not relevant.
4. **Set the parent's value** to the mean of its relevant children.

The values are drawn as research R3's table sets out, each rounded to the field's decimal places:

- conductivity is lognormal with a median of 2.5, clamped to 0.8–6
- the target heat flow is lognormal with a median of 65 on land and 95 at sea
- the gradient is the target divided by the conductivity, clamped below 300
- uncertainties are 5–25 % of the value

Once a dataset's records exist, `build()` writes the rest in bulk:

- **Corrections**: each child gets corrections from `VALID_STATUS_FOR_TYPE`, and probe children
  always get a `T` correction. They are written with one `HeatFlowCorrection.objects.bulk_create`
  per dataset.
- **Probe metadata**: probe intervals get `ProbeMetadata`, written with `bulk_create`.
- **Concepts**: every `ConceptManyToManyField` gets one concept from its vocabulary, written as
  through rows with `<Model>.<field>.through.objects.bulk_create`. That covers:
  - the site's `explo_purpose`
  - the child's `method`
  - the gradient's `method_top`, `method_bottom`, `correction_top` and `correction_bottom`
  - the conductivity's seven fields
  - the probe's `probe_type`

  The concepts are read once into a dict of lists, cached on the instance.
- **Published identifiers**: in a published dataset, `ghfdb_id` is set from `next_ghfdb_id()` on
  each parent and child as it is created.

The constants are `SITES_PER_DATASET = 20` and `CHILDREN_CYCLE`. Nothing in the module imports from
`review` or `ghfdb`.

### `project/review/management/commands/seed_demo_data.py`: the command

**Options**: `--size`, an int, defaults to `DEFAULT_SIZE = 20` and accepts `MIN_SIZE = 4` to
`MAX_SIZE = 200`. Outside that range the command raises `CommandError` naming the range, before
anything is written (FR-010).

**`handle()`**:

1. **Refuse production.** If
   `apps.get_app_config("fairdm").resolved_environment() not in NON_PRODUCTION_ENVIRONMENTS`, raise
   `CommandError` and write nothing (FR-016).
2. **Load the vocabularies and licences.** `call_command("preload")`, then
   `call_command("seed_licenses")` (FR-006).
3. **Create the accounts.** `call_command("create_dev_accounts")`, then `ensure_demo_accounts()`,
   which creates or reuses the fleet accounts:
   - `regular.user`, `staff.user` (`is_staff`) and `super.user` (superuser), all `@example.com`
   - `data-assessor.user@example.com`, in the `Data Assessor` group
   - `data-curator.user@example.com`, in the `Data Curator` group. That group is created by
     `PortalRoles.reconcile()` on `post_migrate`, and by the conftest in tests.

   Each account has the password `password` and a confirmed `EmailAddress`, as
   `create_dev_accounts` sets them. An existing account is reused with its groups added and nothing
   else changed.
4. **Prepare the run.** Set `rng = random.Random()`. Start a `next_ghfdb_id` counter at one above
   the highest `ghfdb_id` across `ParentHeatFlow` and `HeatFlow`, read once.
5. **Create each dataset.** For `i` in `range(size)`, inside `with transaction.atomic(),
   Recalculation.deferred():`, take these steps:
   1. Choose the state. For `i < 4` it is `STATE_PLAN[i]`. After that it is COMPLETE when `i % 5`
      is not 0, and `STATE_PLAN[i % 4]` otherwise. `STATE_PLAN` runs DESCRIBED, AWAITING_DECISION,
      CHANGES_REQUESTED, COMPLETE.
   2. Create a `LiteratureItem` with `citation_key=f"demo-{uuid}"`. Its CSL `item` holds a title,
      authors, a year and `DOI: 10.5072/demo.<uuid>`.
   3. Create the `Dataset`:
      - a name from a small word list
      - `reference=literature`
      - `options={"demo_data": True}`
      - the default licence
      - `visibility=PUBLIC` and `published=True` when COMPLETE, private otherwise
   4. Create a `DatasetLiteratureRelation` of type `IsCitedBy`.
   5. Credit one to three demo people. Each person has an address
      `<given>.<family>@demo.example` and is reused across datasets with `get_or_create`. Credit
      them with `Contribution.add_to`, with the roles `Creator`, `ContactPerson` and
      `DataCollector`.
   6. Create the `Review`:
      - `uploaded_by` is the demo assessor, who is also in `reviewers`
      - `state` is the state chosen in step 1
      - for CHANGES_REQUESTED and COMPLETE, `decided_by` is the demo curator and `decided_at` is
        now. CHANGES_REQUESTED also gets a `decision_comment`.
      - the start and end dates are set
   7. Build the graph:
      `DemoGraph(dataset, rng, next_ghfdb_id if state == COMPLETE else None).build()`.
6. **Report.** Print one line per dataset at verbosity 2, and the totals of datasets, sites and
   children at the end.

No `is_demo(dataset)` helper is needed. The mark is `options__demo_data=True`, and the tests query
it directly.
