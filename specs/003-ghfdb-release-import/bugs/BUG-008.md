# Bug Report: GradientWidget Rejects Valid Numeric T_grad_mean Values

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-ghfdb-import-export
**Reported**: 2026-04-16
**Status**: Patched
**Patched**: 2026-04-16

## Description

When importing child records via `GHFDBChildImportResource`, any row where the XLSX loader
delivers `T_grad_mean` as a native Python `int` or `float` (which is the normal output of
openpyxl/tablib for numeric cells) is rejected with:

> `Line number: 1 - Column 'T_grad_mean' contains a non-text value 800; expected a text string.`

This error is wrong: `T_grad_mean` maps to the `value` field on `ThermalGradient`, which is
a Pint quantity field. Numeric inputs are not only valid — they are the **expected** type for
this column. The import pipeline should create a `ThermalGradient` with `value = 800 K/km`,
not reject the row.

**Observed behaviour**: Any row with a numeric `T_grad_mean` cell is rejected with the
descriptive `ValueError` introduced by BUG-007.

**Expected behaviour**: A numeric `T_grad_mean` value (e.g. `800`) is treated as "present",
the sentinel check passes, and `GradientWidget.clean()` proceeds to create a `ThermalGradient`
whose `value` is `Quantity(800, "K/km")`.

---

## Root Cause Analysis

The BUG-007 fix (T080) added a `try/except AttributeError` guard around the sentinel column
check in `RelatedModelWidget.clean()` (`widgets.py`):

```python
if self.sentinel_column is not None:
    raw_sentinel = (row or {}).get(self.sentinel_column)
    try:
        sentinel_val = (raw_sentinel or "").strip()
    except AttributeError:
        raise ValueError(
            _("Column '%(col)s' contains a non-text value %(val)r; expected a text string.")
            % {"col": self.sentinel_column, "val": raw_sentinel}
        ) from None
    if not sentinel_val:
        return None
```

The guard was designed for **text** sentinel columns (e.g. `name` on `ParentWidget`) where
receiving a number genuinely is an error. However, `GradientWidget` uses `sentinel_column="T_grad_mean"` and `ConductivityWidget` uses `sentinel_column="tc_mean"` — both of which are
**quantity fields** handled downstream by `QuantityWidget`. For these widgets, a numeric
sentinel value is not an error; it is the happy path.

The BUG-007 spec explicitly limited its scope to "a widget that **expects a text string**"
(US2 Acceptance Scenario 8), but the implementation applied the same guard uniformly to all
`RelatedModelWidget` subclasses, including those whose sentinel columns hold numeric data.

The T079 regression tests reinforced this mistake by asserting that
`GradientWidget.clean(row={"T_grad_mean": 1, ...})` raises `ValueError` — when the correct
behaviour is to proceed and produce a `ThermalGradient`.

## Recommended Fix

Update `RelatedModelWidget.clean()` sentinel check to handle numeric types as "present"
rather than erroring:

```python
if self.sentinel_column is not None:
    raw_sentinel = (row or {}).get(self.sentinel_column)
    # Numeric values are valid for quantity-type sentinel columns — treat as present.
    if isinstance(raw_sentinel, (int, float)):
        pass  # proceed: non-None number means the sub-record should be created
    elif raw_sentinel is None or not str(raw_sentinel).strip():
        return None
    # (The text-sentinel guard in ParentWidget.clean() is unaffected — it still
    #  correctly raises ValueError when 'name' holds a number, because a numeric
    #  site name is always a data error.)
```

`ParentWidget.clean()` (which overrides `clean()` and has its own explicit guard for `name`)
is **unaffected** and should continue raising `ValueError` for numeric names, as that remains
an error.

Update T079 regression tests so that:

- `test_related_model_widget_numeric_sentinel_raises_valueerror` is replaced by a test
  asserting `GradientWidget.clean(row={"T_grad_mean": 800, ...})` succeeds and returns a
  `ThermalGradient` instance with a Pint quantity value
- `test_conductivity_widget_numeric_sentinel_raises_valueerror` is similarly replaced by a
  success assertion for `ConductivityWidget` with a numeric `tc_mean`
