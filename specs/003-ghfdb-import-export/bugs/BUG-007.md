# Bug Report: Widget `AttributeError` on Non-Text Cell Values Gives Unhelpful Error

**Type**: Untested flow
**Severity**: Medium
**Feature**: 003-ghfdb-import-export
**Reported**: 2026-04-16
**Status**: Patched
**Patched**: 2026-04-16

## Description

When importing child records, users encounter the error:

> `Line number: 1 - 'int' object has no attribute 'strip'`

This occurs when a spreadsheet cell that the importer expects to contain text (e.g. a controlled-vocabulary label or a site name) is loaded as a numeric type by openpyxl/tablib. This is possible when a user has entered a value that the XLSX loader interprets as a number — for example, entering `1` into a vocabulary column, or leaving a formula that evaluates to a number in a text field.

The raw `AttributeError` from Python is surfaced directly to the user with no indication of which column caused the problem or how to fix it. This makes the error effectively unactionable.

**Observed behaviour**: `'int' object has no attribute 'strip'` at line 1 (or any data row), with no column or field name.

**Expected behaviour**: A descriptive `ValueError` identifying the column name and the unexpected type, e.g.:
> `Column 'q_method' received a non-text value (42); expected a vocabulary label for HeatFlowMethod. Check that the cell contains text, not a number.`

**Root cause (code locations)**: Several widget `clean()` methods call `.strip()` — or call `super().clean()` which delegates to `CharWidget.clean()` which calls `.strip()` — without guarding against non-string types:

1. **`ConceptWidget.clean()`** (`widgets.py`): calls `super().clean(value, row, **kwargs)` which invokes `CharWidget.clean()`. The `import_export` `CharWidget.clean()` implementation calls `value.strip()` unconditionally, so any `int` or `float` cell value raises `AttributeError` here with no column context.

2. **`RelatedModelWidget.clean()` — sentinel column check** (`widgets.py`, line 225): `sentinel_val = ((row or {}).get(self.sentinel_column) or "").strip()`. If the sentinel column holds an integer (e.g. openpyxl read a numeric cell), `(int_value or "")` evaluates to `int_value` (for any non-zero int), and `.strip()` fails with `AttributeError`.

3. **`ParentWidget.clean()` — name sentinel check** (`widgets.py`, line 303): `if not ((row or {}).get("name") or "").strip():` — same pattern, same failure mode if the `name` column holds a number.

## Recommended Fix

Wrap each affected spot in a `try/except AttributeError` block and re-raise a `ValueError` with the column name and actual value. This is more targeted than a blanket `str()` cast and gives users actionable diagnostic information.

**`ConceptWidget.clean()`** — wrap the `super().clean()` call:

```python
def clean(self, value, row=None, **kwargs):
    try:
        val = super().clean(value, row, **kwargs)
    except AttributeError:
        raise ValueError(
            _("Column value %(val)r is not a text string; expected a vocabulary label "
              "for %(vocab)s. Check that the cell contains text and not a number.")
            % {"val": value, "vocab": self.vocabulary.__name__}
        )
    ...
```

**`RelatedModelWidget.clean()` — sentinel check** — wrap with column name context:

```python
if self.sentinel_column is not None:
    raw_sentinel = (row or {}).get(self.sentinel_column)
    try:
        sentinel_val = (raw_sentinel or "").strip()
    except AttributeError:
        raise ValueError(
            _("Column '%(col)s' contains a non-text value %(val)r; expected a text string.")
            % {"col": self.sentinel_column, "val": raw_sentinel}
        )
    if not sentinel_val:
        return None
```

**`ParentWidget.clean()` — name sentinel** — same pattern:

```python
raw_name = (row or {}).get("name")
try:
    if not (raw_name or "").strip():
        return None
except AttributeError:
    raise ValueError(
        _("Column 'name' contains a non-text value %(val)r; expected a site name string.")
        % {"val": raw_name}
    )
```

**Follow-up steps**:

1. Run `/speckit.bugfix.patch` to update spec/plan/tasks artifacts
2. Run `/speckit.bugfix.verify` to confirm consistency
3. Implement the `try/except` guards in `project/ghfdb/resources/widgets.py`
4. Add a regression test in `tests/test_ghfdb/test_resources/testwidgets.py`: assert that passing an `int` to `ConceptWidget.clean()` and to a `RelatedModelWidget` with a numeric sentinel raises a `ValueError` whose message contains the column name

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — Import GHFDB Spreadsheet (Acceptance Scenario 3)
- **Affected requirements**: Scenario 3 — "Given a spreadsheet row with an invalid controlled-vocabulary value, When the importer processes it, Then a descriptive validation error is raised identifying the row number, column name, and invalid value."
- **Gap identified**: Scenario 3 covers invalid *vocabulary values* (i.e. text that doesn't match a concept) but does not cover the case where the cell value is the wrong *Python type* (int/float instead of str). The spec never required widgets to guard against non-string input from the XLSX loader.

### plan.md

- **Affected sections**: Phase 4 widget design constraints (T031/T073 narrative) — the widget contract states "field-level error reporting" but assumes the input is always a string.
- **Impact**: Add a constraint to the widget design: all `Widget.clean()` implementations MUST handle `AttributeError` on `.strip()` calls caused by numeric cell values, and MUST re-raise as `ValueError` with the column name and unexpected value.

### tasks.md

- **Affected tasks**:
  - T031 — `ConceptWidget`, `RelatedModelWidget` implementations: complete but missing the non-string guard
  - T027 — Leaf-widget tests: does not include a test for `int` input to `ConceptWidget.clean()`
  - T028 — `RelatedModelWidget` tests: does not include a test for a numeric sentinel column value
- **False completions**: T031 (widget implementation) and T027/T028 (widget tests) are effectively incomplete with respect to this failure mode
- **Missing tasks**: New task needed — add `try/except AttributeError` guards to `ConceptWidget.clean()`, `RelatedModelWidget.clean()` sentinel check, and `ParentWidget.clean()` name check; add regression tests for numeric cell input to each widget
