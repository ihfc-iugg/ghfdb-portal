# Bug Report: GHFDBImportFormat Reads Metadata Row 8 as First Data Row

**Type**: Spec gap / Implementation drift
**Severity**: High
**Feature**: 003-ghfdb-import-export
**Reported**: 2026-04-15
**Status**: Resolved
**Patched**: 2026-04-15
**Resolved**: 2026-04-15

## Description

The `GHFDBImportFormat.create_dataset()` method in `project/ghfdb/resources/_base.py` starts reading data from row 8 of the GHFDB spreadsheet, but row 8 is a metadata row ("Allowed range of values"), not a data row. The actual first data row is row 9.

The actual GHFDB upload template row structure is:

| Row | Content |
|-----|---------|
| 1 | ID |
| 2 | Obligation |
| 3 | Domain |
| 4 | Quality Relevance |
| 5 | Name |
| 6 | **Short Name** ← column headers (correct) |
| 7 | Unit |
| 8 | Allowed range of values |
| 9+ | **Data rows** ← must start here |

The current code uses `ws.iter_rows(min_row=8, values_only=True)`, which reads row 8 ("Allowed range of values") as the first data record.  This causes every real GHFDB upload to produce garbage on the first imported row — or validation errors if the "Allowed range of values" metadata strings are fed into field validators.

The previous implementation in `project/ghfdb/resources.py` (the legacy monolithic file) correctly used `islice(sheet.rows, 8, None)` (i.e., `skip_rows = 8`), which skips row indexes 0–7 (rows 1–8 in 1-based numbering) and starts reading from row 9. The rewrite to `min_row=8` introduced an off-by-one regression.

## Root Cause Analysis

The `_base.py` `GHFDBImportFormat` class was written with the doc comment "Row 7: Human-readable column descriptions (skipped); Row 8+: Data rows." This reflects an incomplete survey of the GHFDB template — only seven metadata rows were counted when there are actually eight (the "Allowed range of values" row was missed). The implementation faithfully followed the incorrect plan docstring, setting `min_row=8` instead of `min_row=9`. The legacy `resources.py` happened to get this right via `skip_rows = 8` with `islice`, but that correct count was not carried over when T024 rewrote the format class from scratch.

## Recommended Fix

1. **Change `min_row=8` → `min_row=9`** in `project/ghfdb/resources/_base.py`:`GHFDBImportFormat.create_dataset()`
2. **Correct the class and method docstrings** to document the true 8-row metadata preamble:
   - Row 7: Unit
   - Row 8: Allowed range of values
   - Row 9+: Data rows
3. **Reopen T024** in `tasks.md`
4. Run `/speckit.bugfix.patch` to propagate the corrected template layout into spec and plan artifacts
5. Run `/speckit.bugfix.verify` to confirm consistency
6. Re-run `poetry run pytest tests/test_ghfdb/ -v` to confirm all import tests pass against the corrected row offset
