# Bug Report: Admin Import View Crashes on GHFDB Resource-Class Hook

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-ghfdb-import-export
**Reported**: 2026-04-14
**Status**: Patched
**Patched**: 2026-04-14

## Description

Navigating to the GHFDB admin import page at `/admin/ghfdb/ghfdb/import/` fails before the form renders with:

`TypeError at /admin/ghfdb/ghfdb/import/`
`GHFDBAdmin.get_import_resource_classes() takes 1 positional argument but 2 were given`

Expected behavior:

- A staff user can open the GHFDB admin import page and select the available import resource classes.

Actual behavior:

- The import page crashes during admin view setup because the `GHFDBAdmin` hook method signature does not match what `ImportExportMixin` calls.

## Root Cause Analysis

This bug is caused by implementation drift at the Django admin integration boundary.

- `GHFDBAdmin` inherits from `ImportExportMixin` in [project/ghfdb/admin.py](project/ghfdb/admin.py).
- The admin class defines `get_import_resource_classes(self)` without accepting the request argument expected by the mixin call site.
- When the admin import view calls this hook with the request object, Python raises `TypeError` because the method signature is too narrow.
- Existing tests cover anonymous redirect behavior and resource behavior in isolation, but they do not exercise the authenticated admin import page where the hook is actually invoked.
