# Bug Report: Import Preview Columns Not Ordered by Spreadsheet Template

**Type**: Spec gap
**Severity**: Low
**Feature**: 003-ghfdb-import-export
**Reported**: 2026-04-15
**Status**: Fixed
**Patched**: 2026-04-15
**Fixed**: 2026-04-15

## Description

On the Django admin import confirm page (the dry-run review step), columns are displayed in Python field-declaration order rather than in the canonical GHFDB spreadsheet template column order.

**Observed**: The import preview for `GHFDBParentImportResource` shows `p_comment` and `corr_HP_flag` immediately after `q_uncertainty`, because those fields are declared first in the resource class. The passthrough fields `name`, `lat_NS`, `long_EW`, `elevation`, `environment` appear later, even though they come before `p_comment` in the GHFDB template.

**Expected**: Columns in the import preview MUST appear in the same left-to-right order as the uploaded spreadsheet template — for the parent resource this is `PARENT_COLUMNS` order; for the child resource this is `GHFDB_COLUMN_ORDER` order. Staff users rely on the preview to verify correctness row-by-row before confirming; a column order that differs from the source file makes that verification error-prone.

**Root cause**: `django-import-export` determines the confirm-page diff table column order via `get_user_visible_fields()` → `get_fields()`, which returns fields in Python class-declaration order. Neither `GHFDBParentImportResource` nor `GHFDBChildImportResource` overrides `get_user_visible_fields()` (or adds a `Meta.import_order`) to enforce template order.

In `GHFDBParentImportResource` the field declarations diverge from `PARENT_COLUMNS` starting at position 4: the resource declares `p_comment` (template position 9) and `corr_HP_flag` (template position 10) before the passthrough fields `name`, `lat_NS`, `long_EW`, `elevation`, `environment`. In `GHFDBChildImportResource` the child-specific fields are grouped by type at the top of the class, while `GHFDB_COLUMN_ORDER` interleaves parent and child columns in a different sequence.

- **Gap identified**: No acceptance criterion specifies that the import confirm-page preview must present columns in the GHFDB spreadsheet template order. The requirement exists for the export (US3, scenario 1: "columns match the official GHFDB spreadsheet schema in the correct order") but was never mirrored for the import preview.

The fix is an override of `get_user_visible_fields()` (or equivalent) in each resource — not a change to internal field mappings or upsert logic.

## Root Cause Analysis

The spec explicitly requires the export to produce columns in canonical GHFDB template order (US3 scenario 1) but contains no equivalent requirement for the import confirm-page preview. When the resources were implemented, field declarations were grouped by semantic role (mapped vs. pass-through) rather than by spreadsheet column position. Because `django-import-export` uses declaration order for the diff headers, the preview now presents a different column sequence than the source file, making staff review harder. The omission is a spec gap, not an implementation error — the resource correctly reads every column; only the display order is wrong.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to:
   - Add an explicit acceptance criterion to US2 in `spec.md` requiring the import confirm-page column order to match the GHFDB spreadsheet template.
   - Add a plan constraint noting the `get_user_visible_fields()` override requirement.
   - Reopen T035 and T036; add new sub-tasks for tests and implementation.
2. Run `/speckit.bugfix.verify` to confirm consistency across `spec.md`, `plan.md`, and `tasks.md`.
3. In `parent.py`: override `get_user_visible_fields()` to return fields sorted by their `column_name`'s position in `PARENT_COLUMNS` (unknown columns sorted to the end).
4. In `child.py`: override `get_user_visible_fields()` to return fields sorted by their `column_name`'s position in `GHFDB_COLUMN_ORDER` (using the canonical spreadsheet header names, not the lowercase Python attribute names).
5. Add regression assertions in `test_parent_import.py` and `test_child_import.py` that `get_user_visible_fields()` returns fields in the exact template order.
