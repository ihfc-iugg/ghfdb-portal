# Bug Report: GHFDB Child Admin Displays Parent Columns Instead of Child Columns

**Type**: Spec conflict
**Severity**: High
**Feature**: 002-ghfdb-proxy
**Reported**: 2026-04-17
**Status**: Patched
**Patched**: 2026-04-17

## Description

The admin changelist for GHFDB child entries is currently showing parent-oriented spreadsheet fields rather than child-oriented fields.

Expected behavior:

- The child admin should prioritize child-related columns.
- The changelist should show the child `local_id` first.
- The changelist should also show the parent identifier and site context fields for orientation only: `ID_parent`, `name`, `lat_NS`, `long_EW`.
- After those informational columns, the child admin should show the child-level fields in this order:
  `qc`, `qc_uncertainty`, `q_method`, `q_top`, `q_bottom`, `probe_penetration`, `publication_reference`, `data_reference`, `relevant_child`, `c_comment`, `corr_IS_flag`, `corr_T_flag`, `corr_S_flag`, `corr_E_flag`, `corr_TOPO_flag`, `corr_PAL_flag`, `corr_SUR_flag`, `corr_CONV_flag`, `corr_HR_flag`, `expedition`, `probe_type`, `probe_length`, `probe_tilt`, `water_temperature`, `geo_lithology`, `geo_stratigraphy`, `T_grad_mean`, `T_grad_uncertainty`, `T_grad_mean_cor`, `T_grad_uncertainty_cor`, `T_method_top`, `T_method_bottom`, `T_shutin_top`, `T_shutin_bottom`, `T_corr_top`, `T_corr_bottom`, `T_number`, `q_date`, `tc_mean`, `tc_uncertainty`, `tc_source`, `tc_location`, `tc_method`, `tc_saturation`, `tc_pT_conditions`, `tc_pT_fuction`, `tc_number`, `tc_strategy`, `Ref_ISGN`.

Actual behavior:

- The current child-side admin is specified and implemented around parent-level columns such as parent `q`, parent uncertainty, site environment, and other parent-oriented summary fields.
- This makes the child changelist unsuitable for inspecting child measurements directly.

## Root Cause Analysis

This bug originates from a specification conflict introduced during the proxy-model split.

- The feature refinement correctly separated parent and child concerns into `GHFDBParent` and `GHFDBChild`.
- However, the child-admin acceptance criteria and task definitions copied the parent-level column order into the child-admin contract.
- The implementation then followed that incorrect contract, so the wrong behavior was reinforced by tests instead of being caught.
- The result is a child admin that does not support the intended operational workflow of reviewing child-level heat-flow records and their associated child metadata.
